# Integration Helper

Справочник системного аналитика по интеграциям между системами: протоколы и технологии, HTTP (методы, все коды состояния, заголовки), проектирование REST API (идемпотентность, пагинация, фильтрация, кэширование, ошибки, версионирование, rate limiting), безопасность (OAuth 2.0, JWT, mTLS, CORS, OWASP), надёжность, спецификации (OpenAPI, AsyncAPI) и шаблон описания интеграции.

Сайт собран на [VitePress](https://vitepress.dev/): контент — обычные Markdown-файлы, есть полнотекстовый поиск, тёмная тема и диаграммы Mermaid.

## Быстрый старт

Нужен [Node.js](https://nodejs.org/) 20 или новее.

```bash
npm install        # установить зависимости (один раз)
npm run dev        # локальный сервер с автообновлением: http://localhost:5173
npm run build      # собрать статический сайт в docs/.vitepress/dist
npm run preview    # посмотреть собранный сайт локально
```

`npm run build` также проверяет битые внутренние ссылки — запускайте его перед коммитом.

## Структура

```
docs/
├── .vitepress/
│   ├── config.mts        # настройки сайта и боковое меню
│   └── theme/            # стили и расширения темы
├── public/               # статические файлы (логотип)
├── index.md              # главная страница
├── guide/                # о справочнике, чек-лист, глоссарий
├── protocols/            # REST, SOAP, GraphQL, gRPC, WebSocket, брокеры...
├── http/                 # основы, методы, коды состояния, заголовки
├── design/               # проектирование REST API
├── security/             # аутентификация, OAuth 2.0, JWT, TLS, CORS, OWASP
├── reliability/          # таймауты, повторы, паттерны, наблюдаемость
├── specs/                # OpenAPI, AsyncAPI, шаблон описания интеграции
├── tools/                # инструменты, curl, тестирование
└── tester/               # API-тестер (в разработке)
```

## Публикация

Сайт публикуется на GitHub Pages автоматически при каждом push в `main`: https://greymiller13.github.io/integration-helper/

Сборку и выкладку выполняет workflow `.github/workflows/deploy.yml`, за ходом можно следить на вкладке **Actions** репозитория. Если сайт не появился, проверьте, что в **Settings → Pages** в поле **Source** выбрано **GitHub Actions**.

Чтобы выложить сайт в другое место: результат сборки (`docs/.vitepress/dist`) — статический сайт, его можно выложить на GitHub Pages, GitLab Pages или любой веб-сервер. Если сайт открывается не из корня домена, а из подпапки (например, `https://user.github.io/integration-helper/`), задайте базовый путь при сборке:

```bash
BASE=/integration-helper/ npm run build
```
