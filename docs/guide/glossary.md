# Глоссарий

Краткие определения терминов, которые встречаются при проектировании интеграций. Термины упорядочены по алфавиту: сначала латиница (A–Z), затем кириллица (А–Я). У каждого термина — ссылка на страницу справочника, где тема раскрыта подробно.

## A {#a}

**Access token (токен доступа)** — короткоживущий токен, который клиент предъявляет API для доступа к ресурсам, обычно в заголовке `Authorization: Bearer ...`. Выдаётся сервером авторизации, может быть непрозрачной строкой или JWT. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**ACL** — два значения. *Access Control List* — список правил «кто к чему имеет доступ» (например, ACL на топики Kafka). *Anti-Corruption Layer* — слой-переводчик между моделью вашей системы и чужой моделью, который не даёт чужим понятиям «протечь» в ваш домен. → [Обзор безопасности](/security/), [Интеграционные паттерны](/reliability/integration-patterns)

**API (Application Programming Interface)** — программный интерфейс, через который одна система предоставляет свои функции и данные другим. В контексте интеграций обычно подразумевается сетевой API: набор эндпоинтов, форматов и правил взаимодействия. → [REST](/protocols/rest)

**API Gateway** — единая точка входа перед набором сервисов: маршрутизация, аутентификация, rate limiting, логирование, трансформация запросов. Снимает сквозные задачи с самих сервисов. → [Интеграционные паттерны](/reliability/integration-patterns)

**API-first** — подход, при котором контракт API проектируется и согласуется **до** написания кода, обычно в виде спецификации OpenAPI. Позволяет потребителю и поставщику работать параллельно (потребитель — на моке). → [OpenAPI](/specs/openapi)

**AsyncAPI** — спецификация для описания асинхронных API: каналов (топиков, очередей), сообщений и их схем, протоколов брокеров. Аналог OpenAPI для событийных интеграций. → [AsyncAPI](/specs/asyncapi)

**At-least-once (как минимум один раз)** — гарантия доставки, при которой сообщение не теряется, но может прийти повторно. Самый распространённый режим брокеров и вебхуков; требует идемпотентной обработки у получателя. → [Брокеры сообщений](/protocols/messaging)

**At-most-once (не более одного раза)** — гарантия доставки, при которой сообщение не дублируется, но может быть потеряно. Подходит для данных, потеря которых некритична (телеметрия). → [Брокеры сообщений](/protocols/messaging)

**Avro** — бинарный формат сериализации со схемой, популярный в Kafka вместе со Schema Registry. Поддерживает правила эволюции схем. → [Форматы данных](/protocols/data-formats)

## B {#b}

**Backoff (отступ)** — увеличение паузы между повторными попытками. Экспоненциальный backoff удваивает паузу после каждой неудачи; добавление случайной составляющей (jitter) не даёт клиентам повторять запросы синхронно. → [Таймауты и повторы](/reliability/timeouts-retries)

**Backpressure (обратное давление)** — механизм, которым получатель сигнализирует отправителю, что не успевает обрабатывать поток, чтобы тот замедлился. Примеры: ограничение окна в HTTP/2 и gRPC, `429 Too Many Requests`, ограничение предвыборки в брокере. → [Паттерны устойчивости](/reliability/resilience-patterns)

**Base64** — способ кодирования двоичных данных в текст из 64 символов. Используется в Basic Auth, JWT (вариант Base64URL), для передачи файлов внутри JSON. Это **не шифрование** — декодируется кем угодно. → [Форматы данных](/protocols/data-formats)

**Basic Authentication** — схема HTTP-аутентификации, при которой логин и пароль передаются в заголовке `Authorization` в Base64. Допустима только поверх TLS. → [Аутентификация](/security/authentication)

**Bearer token** — токен «на предъявителя»: кто его предъявил, тот и получает доступ, без доказательства владения. Поэтому его утечка опасна. Передаётся в заголовке `Authorization: Bearer ...` (RFC 6750). → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**BFF (Backend for Frontend)** — отдельный серверный слой под конкретный клиент (веб, мобильное приложение), который агрегирует вызовы бэкенд-сервисов и отдаёт данные в удобном для этого клиента виде. → [Интеграционные паттерны](/reliability/integration-patterns)

**BOLA (Broken Object Level Authorization)** — уязвимость №1 в OWASP API Security Top 10: API не проверяет, имеет ли клиент право на конкретный объект, и отдаёт чужие данные при подстановке чужого ID. → [OWASP API Top 10](/security/owasp-api)

**Breaking change (ломающее изменение)** — изменение API, после которого существующие клиенты перестают работать: удаление или переименование поля, смена типа, новое обязательное поле в запросе, изменение кодов ответа. Требует новой версии API. → [Версионирование](/design/versioning)

**Bulkhead (переборка)** — паттерн изоляции ресурсов (пулов потоков, соединений) под разные зависимости, чтобы сбой одной не исчерпал ресурсы для остальных. → [Паттерны устойчивости](/reliability/resilience-patterns)

## C {#c}

**Cache-Control** — HTTP-заголовок, управляющий кэшированием: можно ли кэшировать ответ, где, сколько (`max-age`, `no-store`, `no-cache`, `private`). → [Кэширование](/design/caching)

**CDC (Change Data Capture)** — захват изменений из журнала транзакций базы данных и публикация их как событий (например, через Debezium в Kafka). Позволяет интегрироваться без изменения кода системы-источника. → [Интеграционные паттерны](/reliability/integration-patterns)

**Circuit breaker (автоматический выключатель)** — паттерн, при котором после серии ошибок вызовы к зависимости временно прекращаются (цепь «разомкнута»), а клиент сразу получает ошибку или fallback. Защищает от каскадных отказов. → [Паттерны устойчивости](/reliability/resilience-patterns)

**Claim (утверждение)** — пара «ключ-значение» в JWT с информацией о субъекте и токене: `sub`, `iss`, `aud`, `exp`, `scope` и пользовательские поля. → [JWT](/security/jwt)

**Client Credentials** — grant type OAuth 2.0 для межсервисного взаимодействия без участия пользователя: клиент обменивает свои `client_id` и секрет (или сертификат) на access token. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**CloudEvents** — спецификация CNCF единого формата метаданных событий (`id`, `source`, `type`, `time` и др.) независимо от транспорта. Упрощает обмен событиями между разными системами и брокерами. → [Брокеры сообщений](/protocols/messaging)

**Consumer group (группа потребителей)** — в Kafka набор потребителей, совместно читающих топик: каждая партиция в группе читается только одним потребителем. Разные группы читают топик независимо друг от друга. → [Брокеры сообщений](/protocols/messaging)

**Content negotiation (согласование содержимого)** — механизм выбора представления ответа по заголовкам запроса: `Accept` (формат), `Accept-Language` (язык), `Accept-Encoding` (сжатие). → [Медиатипы и согласование](/http/content-negotiation)

**Content-Type** — заголовок с медиатипом тела запроса или ответа, например `application/json`. Неверный или отсутствующий `Content-Type` — частая причина ошибки `415`. → [Заголовки](/http/headers)

**Correlation ID** — сквозной идентификатор, который передаётся через все системы, участвующие в обработке одного запроса или бизнес-операции, и пишется в логи. Позволяет найти все связанные записи при разборе инцидента. → [Наблюдаемость](/reliability/observability)

**CORS (Cross-Origin Resource Sharing)** — механизм, которым сервер разрешает браузеру выполнять запросы к API с другого источника (origin). Касается только браузеров; межсерверные вызовы CORS не ограничивает. → [CORS](/security/cors)

**CQRS (Command Query Responsibility Segregation)** — разделение моделей (а иногда и хранилищ) для изменения данных (команды) и чтения (запросы). Позволяет оптимизировать каждую сторону отдельно ценой согласованности «в конечном счёте». → [Интеграционные паттерны](/reliability/integration-patterns)

**CRUD (Create, Read, Update, Delete)** — четыре базовые операции над данными. В REST обычно соответствуют `POST`, `GET`, `PUT`/`PATCH`, `DELETE`. → [Методы](/http/methods)

**CSRF (Cross-Site Request Forgery)** — атака, при которой вредоносный сайт заставляет браузер пользователя отправить запрос к вашему API с его cookies. Актуальна для API с аутентификацией через cookies; защиты — SameSite cookies, CSRF-токены. → [Обзор безопасности](/security/)

**Cursor (курсор)** — непрозрачный маркер позиции в списке, который сервер возвращает вместе со страницей; клиент передаёт его для получения следующей страницы. Устойчив к вставкам и удалениям во время обхода. → [Пагинация](/design/pagination)

## D {#d}

**Deprecation** — пометка, что эндпоинт, поле или версия API устарели и будут удалены. Сообщается в документации и HTTP-заголовком `Deprecation`, дата удаления — заголовком `Sunset`. → [Версионирование](/design/versioning)

**DLQ (Dead Letter Queue, очередь «мёртвых» писем)** — очередь, куда перемещаются сообщения, которые не удалось обработать после всех попыток. Не даёт «ядовитому» сообщению блокировать поток и сохраняет его для разбора. → [Брокеры сообщений](/protocols/messaging)

**DPoP (Demonstrating Proof of Possession)** — механизм OAuth 2.0 (RFC 9449), привязывающий токен к ключу клиента: с каждым запросом клиент отправляет подписанное доказательство владения ключом. Украденный токен без ключа бесполезен. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

## E {#e}

**Endpoint (эндпоинт)** — конкретная точка доступа API: сочетание HTTP-метода и пути, например `GET /orders/{id}`. Иногда так называют и базовый адрес сервиса. → [Ресурсы и URI](/design/)

**ETag** — заголовок ответа с идентификатором версии представления ресурса. Используется для условных запросов: кэширования (`If-None-Match`) и защиты от потерянных обновлений (`If-Match`). → [Конкурентный доступ](/design/concurrency)

**Event-driven architecture (событийная архитектура)** — архитектура, в которой системы взаимодействуют, публикуя события о произошедших изменениях и подписываясь на них, а не вызывая друг друга напрямую. → [Брокеры сообщений](/protocols/messaging)

**Event sourcing** — подход, при котором состояние объекта хранится не как текущий снимок, а как последовательность всех событий, которые с ним произошли. Текущее состояние вычисляется проигрыванием событий. → [Интеграционные паттерны](/reliability/integration-patterns)

**Eventual consistency (согласованность в конечном счёте)** — модель, при которой данные в разных системах могут временно расходиться, но при отсутствии новых изменений со временем становятся одинаковыми. Типична для асинхронных интеграций. → [Интеграционные паттерны](/reliability/integration-patterns)

**Exactly-once (ровно один раз)** — гарантия, что сообщение будет обработано ровно один раз. В распределённых системах в чистом виде недостижима; на практике её добиваются комбинацией at-least-once и идемпотентной обработки (effectively-once). → [Идемпотентность](/design/idempotency)

## F {#f}

**Fallback (запасной вариант)** — поведение при недоступности зависимости: значение по умолчанию, данные из кэша, упрощённый ответ, постановка в очередь. → [Паттерны устойчивости](/reliability/resilience-patterns)

**Fan-out (веерная рассылка)** — доставка одного сообщения сразу нескольким получателям (например, через exchange типа fanout в RabbitMQ или несколько групп потребителей в Kafka). → [Брокеры сообщений](/protocols/messaging)

## G {#g}

**gRPC** — фреймворк удалённого вызова процедур от Google поверх HTTP/2 с контрактом на Protocol Buffers. Поддерживает потоковую передачу в обе стороны, эффективен для межсервисного взаимодействия. → [gRPC](/protocols/grpc)

**GraphQL** — язык запросов к API, в котором клиент сам указывает, какие поля и связанные объекты ему нужны, и получает их одним запросом к одному эндпоинту. → [GraphQL](/protocols/graphql)

## H {#h}

**HATEOAS (Hypermedia as the Engine of Application State)** — принцип REST, по которому ответ содержит ссылки на допустимые следующие действия, а клиент переходит по ним, а не конструирует URL сам. → [REST](/protocols/rest)

**Health check** — служебный эндпоинт (например, `/health`), по которому мониторинг и балансировщики проверяют, жив ли сервис и готов ли принимать трафик. → [Наблюдаемость](/reliability/observability)

**HMAC (Hash-based Message Authentication Code)** — код аутентичности сообщения, вычисляемый хеш-функцией с общим секретным ключом. Используется для подписи вебхуков и запросов: получатель проверяет, что сообщение отправил владелец ключа и его не изменили. → [Webhooks](/protocols/webhooks)

**HSTS (HTTP Strict Transport Security)** — заголовок `Strict-Transport-Security`, которым сервер требует от браузера обращаться к нему только по HTTPS в течение заданного времени. → [TLS и mTLS](/security/tls)

**HTTP (HyperText Transfer Protocol)** — протокол прикладного уровня «запрос-ответ», основа REST и большинства веб-API. Семантика описана в RFC 9110. → [Основы HTTP](/http/basics)

**HTTP/2** — версия HTTP с бинарным форматом кадров, мультиплексированием множества запросов в одном TCP-соединении и сжатием заголовков. Обязательна для gRPC. → [Основы HTTP](/http/basics)

**HTTP/3** — версия HTTP поверх протокола QUIC (на базе UDP). Быстрее устанавливает соединение и не страдает от блокировки всех потоков при потере одного пакета. → [Основы HTTP](/http/basics)

## I {#i}

**Idempotency key (ключ идемпотентности)** — уникальный идентификатор операции, который клиент передаёт в запросе (обычно заголовок `Idempotency-Key`). Сервер запоминает результат и при повторе с тем же ключом возвращает его, не выполняя операцию заново. → [Идемпотентность](/design/idempotency)

**IdP (Identity Provider, поставщик удостоверений)** — система, которая аутентифицирует пользователей и выдаёт токены другим приложениям (Keycloak, Azure AD / Entra ID, корпоративный SSO). → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**Introspection (интроспекция)** — два значения. *Token introspection* (RFC 7662) — эндпоинт сервера авторизации, у которого API может спросить, действителен ли токен и какие у него права. *GraphQL introspection* — запрос схемы GraphQL-сервиса, который в проде часто отключают. → [OAuth 2.0 и OpenID Connect](/security/oauth2), [GraphQL](/protocols/graphql)

## J {#j}

**JSON (JavaScript Object Notation)** — текстовый формат данных из объектов, массивов, строк, чисел, `true`/`false` и `null`. Основной формат REST API (RFC 8259). → [Форматы данных](/protocols/data-formats)

**JSON Schema** — язык описания структуры JSON-документов: типы, обязательные поля, ограничения. Используется для валидации и лежит в основе схем OpenAPI 3.1. → [OpenAPI](/specs/openapi)

**JSON-RPC** — лёгкий протокол удалённого вызова процедур: клиент отправляет JSON с именем метода и параметрами, сервер возвращает результат или ошибку. → [JSON-RPC](/protocols/json-rpc)

**JWE (JSON Web Encryption)** — формат зашифрованного токена (RFC 7516). В отличие от обычного подписанного JWT, содержимое JWE нельзя прочитать без ключа. → [JWT](/security/jwt)

**JWKS (JSON Web Key Set)** — набор публичных ключей в формате JSON, публикуемый сервером авторизации по известному адресу. API берёт оттуда ключ для проверки подписи JWT; так же поддерживается ротация ключей. → [JWT](/security/jwt)

**JWS (JSON Web Signature)** — формат подписанных данных (RFC 7515). Обычный JWT — это JWS: содержимое читается всеми, но подделать его без ключа нельзя. → [JWT](/security/jwt)

**JWT (JSON Web Token)** — компактный токен из трёх частей в Base64URL (заголовок, полезная нагрузка с claims, подпись), разделённых точками (RFC 7519). Позволяет проверить токен без обращения к серверу авторизации. → [JWT](/security/jwt)

## K {#k}

**Kafka** — распределённая платформа потоковой передачи событий: хранит сообщения в партиционированных журналах (топиках) заданное время, позволяет многим группам потребителей читать их независимо и перечитывать. → [Брокеры сообщений](/protocols/messaging)

**Keyset pagination (пагинация по ключу)** — пагинация, при которой следующая страница запрашивается условием «после последнего полученного значения ключа сортировки» (например, `id > 1050`). Работает быстро на больших объёмах и не даёт пропусков при вставках. → [Пагинация](/design/pagination)

## L {#l}

**Latency (задержка, латентность)** — время от отправки запроса до получения ответа. Измеряется в перцентилях (p50, p95, p99), а не средним значением. → [Наблюдаемость](/reliability/observability)

**Long polling (длинный опрос)** — техника, при которой сервер держит запрос открытым, пока не появятся новые данные или не истечёт таймаут, после чего клиент сразу отправляет следующий запрос. → [SSE и Long Polling](/protocols/sse)

## M {#m}

**Mock (мок)** — имитация внешней системы или её API для разработки и тестирования: возвращает заранее заданные ответы. В тестировании иногда различают mock (проверяет, какие вызовы пришли) и stub (просто отвечает). → [Тестирование API](/tools/testing)

**mTLS (mutual TLS, взаимный TLS)** — режим TLS, в котором не только сервер, но и клиент предъявляет сертификат. Обеспечивает взаимную аутентификацию систем на транспортном уровне. → [TLS и mTLS](/security/tls)

**MQTT** — лёгкий протокол публикации-подписки для IoT и нестабильных сетей: брокер, иерархические топики, три уровня QoS. → [Брокеры сообщений](/protocols/messaging)

**Multipart** — формат тела `multipart/form-data`, состоящего из нескольких частей с собственными заголовками. Используется для загрузки файлов вместе с полями формы. → [Медиатипы и согласование](/http/content-negotiation)

## N {#n}

**N+1 (проблема N+1 запросов)** — антипаттерн, при котором для получения списка из N объектов со связанными данными выполняется 1 запрос за список и ещё N запросов за деталями каждого объекта. Решается встраиванием связанных данных, пакетными запросами, DataLoader в GraphQL. → [GraphQL](/protocols/graphql)

**NDJSON (Newline Delimited JSON)** — формат, где каждая строка — отдельный JSON-объект. Удобен для потоковой передачи и больших выгрузок: можно обрабатывать по строке, не загружая всё в память. → [Форматы данных](/protocols/data-formats)

## O {#o}

**OAuth 2.0** — фреймворк делегированной авторизации (RFC 6749): клиент получает от сервера авторизации access token с ограниченными правами (scope) и использует его для доступа к API. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**OData (Open Data Protocol)** — стандарт REST-API с единым языком запросов в URL (`$filter`, `$select`, `$expand`, `$orderby`) и машиночитаемыми метаданными. Распространён в продуктах Microsoft и SAP. → [OData](/protocols/odata)

**Offset pagination (пагинация по смещению)** — пагинация параметрами `offset` и `limit` (или `page` и `size`). Проста, но медленна на больших смещениях и даёт пропуски и дубли при изменении данных во время обхода. → [Пагинация](/design/pagination)

**OIDC (OpenID Connect)** — слой аутентификации поверх OAuth 2.0: добавляет ID token (JWT с информацией о пользователе), эндпоинт UserInfo и стандартное обнаружение настроек. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**OpenAPI** — стандарт машиночитаемого описания REST API в YAML или JSON: пути, методы, параметры, схемы, коды ответов, безопасность. По нему генерируют документацию, клиентов, моки и тесты. → [OpenAPI](/specs/openapi)

**Optimistic locking (оптимистичная блокировка)** — защита от потерянных обновлений без блокировок: при изменении клиент передаёт версию объекта (`If-Match` с ETag), и сервер отклоняет изменение с `412`, если объект уже изменился. → [Конкурентный доступ](/design/concurrency)

**Outbox (транзакционный outbox)** — паттерн надёжной публикации событий: событие записывается в таблицу outbox в той же транзакции, что и бизнес-изменение, а отдельный процесс отправляет его в брокер. Исключает ситуацию «данные сохранили, событие потеряли». → [Интеграционные паттерны](/reliability/integration-patterns)

**OWASP API Security Top 10** — перечень десяти самых критичных рисков безопасности API от сообщества OWASP: BOLA, нарушения аутентификации, избыточная выдача данных, отсутствие ограничений ресурсов и др. → [OWASP API Top 10](/security/owasp-api)

## P {#p}

**Partition (партиция)** — часть топика Kafka, упорядоченный журнал сообщений. Порядок гарантируется только внутри партиции; сообщения с одинаковым ключом попадают в одну партицию. → [Брокеры сообщений](/protocols/messaging)

**Payload (полезная нагрузка)** — содержательная часть сообщения или запроса (обычно тело), в отличие от служебных данных (заголовков, метаданных). Также — вторая часть JWT с claims. → [Основы HTTP](/http/basics)

**Pessimistic locking (пессимистичная блокировка)** — блокировка объекта на время изменения, чтобы другие не могли его менять. В HTTP API применяется редко, так как требует состояния между запросами. → [Конкурентный доступ](/design/concurrency)

**PKCE (Proof Key for Code Exchange)** — расширение OAuth 2.0 (RFC 7636) для Authorization Code flow: клиент доказывает, что именно он начал авторизацию, через одноразовый секрет. Обязательно для мобильных и браузерных приложений, рекомендовано для всех. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**Polling (опрос)** — периодические запросы клиента к серверу для проверки изменений. Прост, но создаёт лишнюю нагрузку и задержку; альтернативы — вебхуки, SSE, брокеры. → [SSE и Long Polling](/protocols/sse)

**Preflight (предварительный запрос)** — запрос `OPTIONS`, который браузер автоматически отправляет перед «непростым» кросс-доменным запросом, чтобы узнать, разрешает ли сервер такой метод и заголовки. → [CORS](/security/cors)

**Problem Details** — стандартный формат описания ошибок в HTTP API (RFC 9457, ранее RFC 7807): JSON с полями `type`, `title`, `status`, `detail`, `instance` и медиатипом `application/problem+json`. → [Ошибки](/design/errors)

**Protobuf (Protocol Buffers)** — бинарный формат сериализации от Google со схемой в `.proto`-файлах. Компактнее и быстрее JSON, используется в gRPC. → [gRPC](/protocols/grpc)

**Pub/Sub (публикация-подписка)** — модель обмена, при которой отправитель публикует сообщения в топик, не зная получателей, а все подписчики получают свою копию. → [Брокеры сообщений](/protocols/messaging)

## Q {#q}

**QoS (Quality of Service)** — в MQTT уровень гарантии доставки: 0 — не более одного раза, 1 — как минимум один раз, 2 — ровно один раз (между клиентом и брокером). В RabbitMQ prefetch-настройка тоже называется QoS. → [Брокеры сообщений](/protocols/messaging)

**Query string (строка запроса)** — часть URL после `?` с параметрами вида `ключ=значение`, разделёнными `&`. Используется для фильтрации, сортировки, пагинации. → [Фильтрация и сортировка](/design/filtering)

## R {#r}

**RabbitMQ** — брокер сообщений на основе AMQP: сообщения публикуются в exchange и маршрутизируются в очереди по правилам (bindings). Удобен для очередей задач и гибкой маршрутизации. → [Брокеры сообщений](/protocols/messaging)

**Rate limiting (ограничение частоты)** — ограничение количества запросов от клиента за интервал времени. При превышении сервер отвечает `429 Too Many Requests`, часто с `Retry-After`. → [Rate limiting](/design/rate-limiting)

**Refresh token** — долгоживущий токен, которым клиент получает новый access token без повторной аутентификации пользователя. В Client Credentials обычно не используется. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**Resource (ресурс)** — ключевая абстракция REST: любой именуемый объект или коллекция (заказ, клиент, список заказов), имеющий URI и представления. → [Ресурсы и URI](/design/)

**REST (Representational State Transfer)** — архитектурный стиль для сетевых API: ресурсы с URI, единый интерфейс методов HTTP, отсутствие состояния сессии на сервере, кэшируемость. → [REST](/protocols/rest)

**Retry (повтор)** — повторная отправка запроса после временной ошибки. Безопасен только для идемпотентных операций; требует ограничения числа попыток и backoff. → [Таймауты и повторы](/reliability/timeouts-retries)

**Retry-After** — заголовок ответа, сообщающий клиенту, через сколько секунд (или после какой даты) можно повторить запрос. Используется с кодами `429` и `503`. → [Rate limiting](/design/rate-limiting)

**RPC (Remote Procedure Call)** — стиль взаимодействия «вызов удалённой функции»: клиент вызывает метод с параметрами и получает результат. Реализации — gRPC, JSON-RPC, SOAP. → [Обзор и выбор технологии](/protocols/)

**RPS (Requests Per Second)** — количество запросов в секунду, основная метрика нагрузки и пропускной способности API. → [Тестирование API](/tools/testing)

## S {#s}

**Saga (сага)** — паттерн выполнения бизнес-транзакции, затрагивающей несколько систем, как последовательности локальных транзакций с компенсирующими действиями на случай сбоя. Может быть оркестрируемой или хореографической. → [Интеграционные паттерны](/reliability/integration-patterns)

**Schema Registry (реестр схем)** — сервис хранения версий схем сообщений (Avro, Protobuf, JSON Schema) для брокера, проверяющий совместимость новых версий с предыдущими. → [Брокеры сообщений](/protocols/messaging)

**Scope (область доступа)** — в OAuth 2.0 обозначение набора прав, запрашиваемых клиентом и выданных в токене, например `orders.read`. → [OAuth 2.0 и OpenID Connect](/security/oauth2)

**SDK (Software Development Kit)** — набор библиотек для работы с API на конкретном языке программирования. Часто генерируется из спецификации OpenAPI. → [OpenAPI](/specs/openapi)

**Semantic versioning (семантическое версионирование, SemVer)** — схема номеров версий `MAJOR.MINOR.PATCH`: мажорная версия растёт при ломающих изменениях, минорная — при обратно совместимых новых функциях, патч — при исправлениях. → [Версионирование](/design/versioning)

**SLA / SLO / SLI** — *SLI* (индикатор) — измеряемая метрика качества (доля успешных запросов, p95 латентности). *SLO* (цель) — целевое значение SLI («99,9% успешных запросов за месяц»). *SLA* (соглашение) — договорное обязательство с последствиями при нарушении. → [Наблюдаемость](/reliability/observability)

**SOAP** — протокол обмена XML-сообщениями с конвертом (Envelope), строгим контрактом в WSDL и расширениями WS-* (безопасность, надёжная доставка). Распространён в корпоративных и государственных системах. → [SOAP](/protocols/soap)

**SSE (Server-Sent Events)** — стандарт однонаправленной потоковой передачи событий от сервера клиенту поверх обычного HTTP-соединения (`text/event-stream`), с автоматическим переподключением. → [SSE и Long Polling](/protocols/sse)

**Stateless (без состояния)** — свойство взаимодействия, при котором каждый запрос содержит всю информацию для своей обработки, а сервер не хранит контекст сессии между запросами. Упрощает масштабирование. → [REST](/protocols/rest)

**Sunset** — HTTP-заголовок (RFC 8594) с датой, после которой ресурс или версия API перестанут быть доступны. → [Версионирование](/design/versioning)

## T {#t}

**Throttling (троттлинг)** — замедление или ограничение обработки запросов при превышении допустимой нагрузки. Часто используется как синоним rate limiting, но может означать и замедление вместо отказа. → [Rate limiting](/design/rate-limiting)

**Throughput (пропускная способность)** — количество операций, которое система обрабатывает за единицу времени (RPS, сообщений в секунду, МБ/с). → [Наблюдаемость](/reliability/observability)

**TLS (Transport Layer Security)** — криптографический протокол, обеспечивающий шифрование, целостность и аутентификацию сервера (а при mTLS — и клиента). HTTPS — это HTTP поверх TLS. Актуальные версии — 1.2 и 1.3. → [TLS и mTLS](/security/tls)

**Token bucket (корзина токенов)** — алгоритм rate limiting: корзина пополняется токенами с постоянной скоростью до ёмкости, каждый запрос забирает токен. Позволяет кратковременные всплески в пределах ёмкости. → [Rate limiting](/design/rate-limiting)

**Tracing (распределённая трассировка)** — сбор цепочки вызовов одного запроса через все сервисы с временем каждого этапа. Контекст передаётся заголовком `traceparent` (W3C Trace Context). → [Наблюдаемость](/reliability/observability)

**TTL (Time To Live)** — время жизни данных: записи в кэше, сообщения в очереди, ключа идемпотентности, DNS-записи. После истечения TTL данные удаляются или считаются устаревшими. → [Кэширование](/design/caching)

## U {#u}

**URI / URL / URN** — *URI* (Uniform Resource Identifier) — общий идентификатор ресурса (RFC 3986). *URL* — URI, указывающий, где и как получить ресурс (`https://api.example.com/orders/42`). *URN* — URI-имя без указания местоположения (`urn:isbn:9785000000000`). → [Ресурсы и URI](/design/)

**UUID (Universally Unique Identifier)** — 128-битный идентификатор, который можно генерировать независимо без координации (RFC 9562). Версия 4 — случайная, версия 7 — упорядоченная по времени, удобна для индексов БД. → [Соглашения о данных](/design/data-conventions)

## V {#v}

**Vary** — заголовок ответа, перечисляющий заголовки запроса, от которых зависит ответ (например, `Vary: Accept-Language`). Кэши должны хранить разные копии для разных значений этих заголовков. → [Кэширование](/design/caching)

## W {#w}

**Webhook (вебхук)** — HTTP-вызов, который система-поставщик отправляет на заранее зарегистрированный URL потребителя при наступлении события. «Обратный API»: не клиент опрашивает сервер, а сервер уведомляет клиента. → [Webhooks](/protocols/webhooks)

**WebSocket** — протокол постоянного двунаправленного соединения поверх TCP (RFC 6455), устанавливаемого через HTTP Upgrade. Подходит для чатов, котировок, совместного редактирования. → [WebSocket](/protocols/websocket)

**WSDL (Web Services Description Language)** — XML-описание SOAP-сервиса: операции, сообщения, типы данных (через XSD), адреса и привязки к протоколам. → [SOAP](/protocols/soap)

## X {#x}

**XML (eXtensible Markup Language)** — текстовый формат разметки данных с тегами и атрибутами. Основа SOAP, распространён в корпоративных и государственных интеграциях. → [Форматы данных](/protocols/data-formats)

**XSD (XML Schema Definition)** — язык описания структуры XML-документов: элементы, типы, обязательность, ограничения. Используется для валидации и в WSDL. → [SOAP](/protocols/soap)

## Y {#y}

**YAML** — человекочитаемый формат данных на отступах, надмножество JSON. Основной формат для спецификаций OpenAPI и AsyncAPI и конфигураций. → [Форматы данных](/protocols/data-formats)

## А {#ru-a}

**Авторизация (authorization)** — проверка, **что** разрешено делать уже аутентифицированному субъекту: какие операции и над какими объектами. Ошибка авторизации — `403 Forbidden`. → [Обзор безопасности](/security/)

**Асинхронное взаимодействие** — обмен, при котором отправитель не ждёт результата обработки: отправляет сообщение или получает `202 Accepted` и узнаёт результат позже (событием, вебхуком, опросом статуса). → [Асинхронные операции](/design/async-operations)

**Аутентификация (authentication)** — проверка, **кто** обращается: пользователь или система подтверждает свою личность (паролем, токеном, сертификатом). Ошибка аутентификации — `401 Unauthorized`. → [Аутентификация](/security/authentication)

## Б {#ru-b}

**Брокер сообщений (message broker)** — промежуточное ПО, которое принимает сообщения от отправителей, хранит и доставляет их получателям. Развязывает системы во времени и по доступности. Примеры — Kafka, RabbitMQ, ActiveMQ. → [Брокеры сообщений](/protocols/messaging)

## В {#ru-v}

**Валидация (validation)** — проверка входных данных на соответствие контракту и бизнес-правилам: типы, обязательность, форматы, диапазоны, допустимые комбинации. Ошибка — `400` или `422` с указанием поля. → [Ошибки](/design/errors)

**Версионирование (versioning)** — управление изменениями API так, чтобы существующие клиенты продолжали работать: номер версии в URL, заголовке или медиатипе, политика поддержки и вывода старых версий. → [Версионирование](/design/versioning)

## Г {#ru-g}

**Гарантия доставки (delivery guarantee)** — обязательство системы обмена относительно потерь и дублей: at-most-once, at-least-once или exactly-once. Определяет, нужна ли получателю дедупликация. → [Брокеры сообщений](/protocols/messaging)

## Д {#ru-d}

**Дедупликация (deduplication)** — отбрасывание повторно полученных сообщений или запросов по их уникальному идентификатору. Обязательна при доставке at-least-once. → [Идемпотентность](/design/idempotency)

## З {#ru-z}

**Заглушка (stub, mock)** — упрощённая имитация внешней системы, возвращающая заранее заданные ответы. Позволяет разрабатывать и тестировать интеграцию, когда реальная система недоступна или не готова. → [Тестирование API](/tools/testing)

**Заголовок HTTP (header)** — пара «имя: значение» в запросе или ответе с метаданными: тип содержимого, авторизация, кэширование, трассировка. → [Заголовки](/http/headers)

## И {#ru-i}

**Идемпотентность (idempotency)** — свойство операции, при котором повторное выполнение с теми же параметрами даёт тот же результат на сервере, что и однократное. `GET`, `PUT`, `DELETE` идемпотентны по определению, `POST` — нет, если не использовать ключ идемпотентности. → [Идемпотентность](/design/idempotency)

**Интеграционная шина (ESB, Enterprise Service Bus)** — централизованное промежуточное ПО для интеграции корпоративных систем: маршрутизация, трансформация форматов, оркестрация, мониторинг. Упрощает подключение, но становится узким местом и точкой отказа. → [Интеграционные паттерны](/reliability/integration-patterns)

## К {#ru-k}

**Код состояния (status code)** — трёхзначное число в HTTP-ответе, обозначающее результат: 2xx — успех, 3xx — перенаправление, 4xx — ошибка клиента, 5xx — ошибка сервера. → [Коды состояния](/http/status-codes)

**Компенсирующая транзакция** — действие, отменяющее эффект ранее выполненного шага распределённой операции (отмена резерва, возврат платежа). Основа паттерна «сага». → [Интеграционные паттерны](/reliability/integration-patterns)

**Контракт (contract)** — формальная договорённость между поставщиком и потребителем о взаимодействии: эндпоинты, форматы, обязательность полей, коды ошибок, нефункциональные требования. Фиксируется в спецификации (OpenAPI, AsyncAPI, WSDL). → [Шаблон описания интеграции](/specs/integration-template)

**Контрактное тестирование** — проверка того, что реализации поставщика и потребителя соответствуют согласованному контракту, без одновременного запуска обеих систем (Pact, валидация по OpenAPI). → [Тестирование API](/tools/testing)

**Кэширование (caching)** — сохранение копии ответа, чтобы повторно отдавать её без обращения к источнику. Снижает нагрузку и задержку, но требует правил актуальности. → [Кэширование](/design/caching)

## М {#ru-m}

**Маппинг (mapping)** — соответствие полей и значений между моделями данных двух систем с правилами преобразования (форматы, справочники, значения по умолчанию). → [Соглашения о данных](/design/data-conventions)

**Медиатип (media type, MIME-тип)** — идентификатор формата данных, например `application/json`, `application/xml`, `text/csv`. Передаётся в `Content-Type` и `Accept`. → [Медиатипы и согласование](/http/content-negotiation)

**Метод HTTP (HTTP method)** — действие над ресурсом: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`. Метод определяет семантику, безопасность и идемпотентность запроса. → [Методы](/http/methods)

## Н {#ru-n}

**Наблюдаемость (observability)** — способность понять, что происходит внутри системы, по её внешним сигналам: логам, метрикам и трассировкам. → [Наблюдаемость](/reliability/observability)

**НСИ (нормативно-справочная информация)** — справочники и классификаторы, общие для нескольких систем: страны, валюты, единицы измерения, статусы, коды подразделений. Расхождения НСИ — частая причина ошибок интеграции. → [Соглашения о данных](/design/data-conventions)

## О {#ru-o}

**Обратная совместимость (backward compatibility)** — свойство новой версии API работать со старыми клиентами без их изменения. Добавление необязательного поля в ответ обычно совместимо, удаление поля — нет. → [Версионирование](/design/versioning)

**Очередь (queue)** — структура брокера, в которой сообщения ждут обработки; каждое сообщение получает один из потребителей очереди. Используется для распределения задач. → [Брокеры сообщений](/protocols/messaging)

## П {#ru-p}

**Пагинация (pagination)** — постраничная выдача больших списков. Основные виды — по смещению (offset), по курсору (cursor) и по ключу (keyset). → [Пагинация](/design/pagination)

**Перцентиль (percentile)** — значение, ниже которого лежит заданная доля измерений. p95 = 300 мс означает, что 95% запросов выполнились быстрее 300 мс. Показывает «хвосты», которые скрывает среднее. → [Наблюдаемость](/reliability/observability)

**Полезная нагрузка** — см. **Payload** в разделе [P](#p). → [Основы HTTP](/http/basics)

**Поставщик (provider, producer)** — система, предоставляющая API или публикующая события. → [Обзор и выбор технологии](/protocols/)

**Потребитель (consumer, client)** — система, вызывающая API или читающая события. → [Обзор и выбор технологии](/protocols/)

**Пропускная способность** — см. **Throughput** в разделе [T](#t). → [Наблюдаемость](/reliability/observability)

## Р {#ru-r}

**Ресурс** — см. **Resource** в разделе [R](#r): именуемый объект или коллекция с собственным URI. → [Ресурсы и URI](/design/)

## С {#ru-s}

**Сериализация (serialization)** — преобразование объекта в последовательность байтов или текст для передачи по сети или хранения (в JSON, XML, Protobuf, Avro). Обратный процесс — десериализация. → [Форматы данных](/protocols/data-formats)

**Синхронное взаимодействие** — обмен, при котором вызывающая сторона ждёт ответа в рамках того же запроса (классический REST, gRPC, SOAP). Простое, но связывает доступность систем. → [Обзор и выбор технологии](/protocols/)

**Спецификация API** — формальное машиночитаемое описание контракта API: OpenAPI для REST, AsyncAPI для событий, WSDL для SOAP, `.proto` для gRPC. → [OpenAPI](/specs/openapi)

## Т {#ru-t}

**Таймаут (timeout)** — максимальное время ожидания операции (соединения, ответа, обработки), после которого она считается неуспешной. Каждый сетевой вызов должен иметь явный таймаут. → [Таймауты и повторы](/reliability/timeouts-retries)

**Топик (topic)** — именованный канал в брокере, в который публикуются сообщения определённого типа и на который подписываются потребители. В Kafka топик делится на партиции. → [Брокеры сообщений](/protocols/messaging)

**Транзакция (transaction)** — группа операций, выполняемых как единое целое: либо все, либо ни одной. Между системами классические транзакции обычно заменяют сагами и паттерном Outbox. → [Интеграционные паттерны](/reliability/integration-patterns)

**Трассировка** — см. **Tracing** в разделе [T](#t). → [Наблюдаемость](/reliability/observability)

## Ф {#ru-f}

**Файловый обмен** — интеграция через передачу файлов (CSV, XML, JSON) по SFTP, в объектное хранилище или общую папку. Подходит для больших пакетов и систем, не умеющих в API. → [Файловый обмен](/protocols/file-exchange)

**Фильтрация (filtering)** — отбор элементов списка по условиям, обычно через параметры строки запроса (`?status=new&createdFrom=2026-01-01`). → [Фильтрация и сортировка](/design/filtering)

## Э {#ru-e}

**Эндпоинт** — см. **Endpoint** в разделе [E](#e): сочетание метода и пути API. → [Ресурсы и URI](/design/)
