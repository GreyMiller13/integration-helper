# Обзор инструментов

Набор инструментов, которыми системный аналитик пользуется при проектировании, отладке и приёмке интеграций: отправить запрос, посмотреть трафик, поднять заглушку, проверить спецификацию, нарисовать схему. Для каждого инструмента указано, для чего он, сколько стоит и чем выделяется.

::: info Про «бесплатно» и «платно»
Условия лицензирования меняются. Пометка «freemium» означает, что есть бесплатный тариф с ограничениями (по числу пользователей, запусков, функциям командной работы). Перед тем как закладывать инструмент в процесс команды, проверьте актуальные условия и требования службы ИБ — особенно для облачных сервисов, куда уходят ваши запросы и токены.
:::

## HTTP-клиенты {#http-clients}

Графические и консольные клиенты для ручной отправки запросов, хранения коллекций и окружений.

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **Postman** | Ручные запросы, коллекции, окружения, автотесты, моки, документация | Freemium | Стандарт де-факто. Поддерживает REST, GraphQL, gRPC, WebSocket, SOAP (как HTTP POST с XML). Коллекции по умолчанию хранятся в облаке Postman — учитывайте требования ИБ. Запуск коллекций из CLI — Newman / Postman CLI |
| **Insomnia** (Kong) | Ручные запросы, дизайн OpenAPI | Open source ядро + платные тарифы | REST, GraphQL, gRPC, WebSocket, SSE. Есть локальное хранилище (без облака) и синхронизация через git |
| **Bruno** | Ручные запросы, коллекции, тесты | Open source + платная редакция | Offline-first, без обязательного аккаунта. **Коллекции хранятся как обычные текстовые файлы в папке** — их удобно класть в git рядом со спецификацией. Есть CLI для CI |
| **Hoppscotch** | Быстрые запросы из браузера | Open source, есть облачный и self-hosted вариант | Лёгкий веб-клиент, REST, GraphQL, WebSocket, SSE, MQTT. Можно развернуть внутри периметра компании |
| **HTTPie** | Запросы из терминала с человекочитаемым синтаксисом | CLI — open source; Desktop/Web — freemium | Команды `http` и `https`, подсветка и форматирование ответа, JSON по умолчанию. Удобнее curl для ручной работы |
| **Thunder Client** | HTTP-клиент внутри VS Code | Freemium | Похож на Postman, но живёт в редакторе. Часть функций (в т. ч. git-синхронизация) — в платной версии |
| **IntelliJ HTTP Client** | Запросы из файлов `.http` в IDE JetBrains | Встроен в IDE JetBrains (в части редакций — платный); CLI `ijhttp` | Файлы `.http` хранятся в репозитории, окружения — в `http-client.env.json`, секреты — в `http-client.private.env.json` (не коммитится). Есть скрипты-проверки ответа на JS |
| **REST Client** (расширение VS Code) | Запросы из файлов `.http` / `.rest` в VS Code | Бесплатно | Простой текстовый формат, переменные, окружения. Файлы — обычный текст, идеально для git и code review |

::: tip Как выбрать
- Нужно работать в команде с бизнес-аналитиками и тестировщиками, есть корпоративная лицензия — Postman.
- Нельзя выносить запросы и токены в облако, коллекции должны лежать в git — Bruno или `.http`-файлы.
- Быстро проверить что-то из терминала или скрипта — curl (см. [шпаргалку](/tools/curl)) или HTTPie.
:::

## curl {#curl}

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **curl** | Отправка запросов из командной строки, скрипты, воспроизведение проблем | Бесплатно, open source | Есть почти везде (Linux, macOS, Windows 10+ как `curl.exe`). Универсальный язык общения: «пришлите curl, которым воспроизводится ошибка». Большинство клиентов (Postman, DevTools, Bruno) умеют импортировать и экспортировать запросы в виде curl-команды |

Подробно — в [шпаргалке curl](/tools/curl).

## SOAP {#soap}

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **SoapUI** (open source) | Импорт WSDL, генерация запросов, функциональные тесты, моки SOAP-сервисов | Бесплатно | Строит шаблоны запросов по WSDL/XSD, валидирует ответ по схеме, умеет WS-Security. Поддерживает и REST, но для REST есть более удобные инструменты |
| **ReadyAPI** (SmartBear) | То же + нагрузочное тестирование, виртуализация сервисов, отчёты | Платно | Коммерческое развитие SoapUI для команд |
| **Postman** | Разовые SOAP-запросы | Freemium | SOAP-запрос — это `POST` с XML-телом и заголовками `Content-Type` / `SOAPAction`. Можно импортировать WSDL, но возможности скромнее SoapUI |

Подробнее о протоколе — [SOAP](/protocols/soap).

## Моки и заглушки {#mocks}

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **Prism** (Stoplight) | Мок-сервер по OpenAPI-спецификации | Бесплатно, open source | Поднимается одной командой из спецификации, отдаёт примеры или сгенерированные данные, **валидирует входящие запросы** по схеме. Режим proxy проверяет ответы реального сервиса на соответствие спецификации |
| **WireMock** | Гибкие заглушки HTTP-сервисов | Open source; WireMock Cloud — платно | Сопоставление запросов по URL, заголовкам, телу; сценарии с состоянием; задержки и сбои (fault injection); запись и воспроизведение реального трафика. Работает как библиотека (Java) и как отдельный сервер / Docker-контейнер |
| **Mockoon** | Мок-сервер с GUI | Бесплатно, open source; облачные функции — платно | Настройка в графическом интерфейсе, импорт OpenAPI, есть CLI для запуска в CI |
| **MockServer** | Заглушки и прокси для тестов | Бесплатно, open source | Java-библиотека и сервер, умеет проверять, какие запросы к нему пришли (verification) |
| **json-server** | Фейковый REST API из JSON-файла за минуту | Бесплатно (npm) | CRUD по `db.json`, фильтрация и пагинация «из коробки». Подходит для прототипов фронтенда, не для имитации реального контракта |

Подробнее о том, как использовать заглушки в тестировании, — [Тестирование API](/tools/testing).

|---|---|---|---|
| **httpbin.org** | Проверка поведения клиента | Бесплатно | Эндпоинты, возвращающие ваш же запрос (`/anything`, `/headers`), нужный код (`/status/503`), задержку (`/delay/5`), редиректы, сжатие, Basic Auth |

| **RequestBin** (Pipedream) | Приём и просмотр входящих запросов | Freemium | Аналог webhook.site |

| **reqres.in** | Фейковый REST API с пользователями и логином | Freemium | Для учебных примеров. Сейчас может требовать бесплатный API-ключ в заголовке |

::: danger Не отправляйте реальные данные
Публичные сервисы видят всё, что вы им отправили, а webhook.site и RequestBin ещё и хранят это. Никаких боевых токенов, персональных данных, данных клиентов. Для работы с реальными данными поднимайте заглушки внутри периметра (WireMock, Mockoon, httpbin в Docker).
:::

## Перехват и отладка трафика {#traffic}

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **DevTools браузера** (вкладка Network) | Запросы веб-приложения: заголовки, тела, тайминги, CORS | Бесплатно | Фильтр Fetch/XHR, «Preserve log» (не терять запросы при переходах), «Copy as cURL», экспорт HAR. Ошибки CORS видны в консоли — см. [CORS](/security/cors) |
| **Fiddler** | HTTP(S)-прокси для перехвата и правки трафика | Fiddler Classic — бесплатно (Windows); Fiddler Everywhere — платно | Расшифровка HTTPS через свой корневой сертификат, правка запросов «на лету», повтор запросов |
| **Charles Proxy** | HTTP(S)-прокси, популярен для мобильных приложений | Платно (есть пробный период) | Throttling (имитация медленной сети), Map Local / Map Remote, breakpoints |
| **mitmproxy** | Консольный и веб-прокси для перехвата | Бесплатно, open source | Скриптуется на Python, есть веб-интерфейс `mitmweb` |
| **Wireshark** | Анализ сетевого трафика на уровне пакетов | Бесплатно, open source | Когда проблема ниже HTTP: TCP, DNS, TLS-рукопожатие, обрывы соединений. HTTPS без ключей сессии не расшифровывает |

::: warning Перехват HTTPS
Прокси-перехватчики расшифровывают HTTPS, подменяя сертификат своим. Клиент должен доверять корневому сертификату прокси. Не устанавливайте такие сертификаты на рабочие машины без согласования с ИБ, и не пытайтесь так обойти certificate pinning в чужих приложениях.
:::

## Работа с данными {#data}

| Инструмент | Для чего | Стоимость | Особенности |
|---|---|---|---|
| **jq** | Фильтрация и преобразование JSON в командной строке | Бесплатно, open source | Вытащить поле, отфильтровать массив, пересобрать объект. Идеальная пара для curl |
| **yq** | То же для YAML (и JSON, XML) | Бесплатно, open source | Есть две разные утилиты с этим именем (на Go от mikefarah и Python-обёртка над jq) — синтаксис отличается, уточняйте, какая установлена |
| **JSON-форматтеры** | Форматирование, валидация, сравнение JSON | Бесплатно | Встроены в IDE и редакторы (VS Code, IntelliJ), Firefox показывает JSON-ответы в удобном виде. Онлайн-форматтеры — только для несекретных данных |
| **jwt.io** | Декодирование и проверка подписи JWT | Бесплатно | Показывает заголовок и claims токена. См. [JWT](/security/jwt) |
| **base64** | Кодирование и декодирование Base64 | Бесплатно | Утилита `base64` в Linux/macOS, `[Convert]::FromBase64String` в PowerShell, `certutil -decode` в Windows |

::: danger Боевые токены — только локально
Не вставляйте production-токены, ключи и персональные данные в онлайн-сервисы, даже если сервис заявляет, что всё обрабатывается в браузере. JWT декодируется без всяких сайтов: это две Base64URL-строки, разделённые точками. Действующий токен — это пропуск в систему: кто его увидел, тот может им воспользоваться до истечения срока жизни.
:::

```bash
# Декодировать payload JWT локально (вторая часть токена)
echo "$TOKEN" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null | jq .
```

## Минимальный набор аналитика {#minimal-kit}

Если ставить с нуля — этого хватает на 90% задач:

1. **curl** + **jq** — воспроизвести запрос, отправить его коллегам, разобрать ответ. Обязательный минимум.
2. **HTTP-клиент с коллекциями** — Postman или Bruno (если коллекции нужно хранить в git) либо `.http`-файлы в IDE.
3. **Браузерные DevTools** — разбираться с запросами фронтенда, CORS, куками.
4. **Swagger Editor** или IDE с плагином OpenAPI + **Spectral** — писать и проверять спецификации.
5. **Мок-сервер** — Prism (если есть OpenAPI) или WireMock / Mockoon — чтобы потребитель мог начать работу до готовности поставщика.
6. **webhook.site** или локальный аналог — посмотреть, что реально отправляет система.
7. **UI для брокера** вашей компании (Kafka UI / AKHQ / RabbitMQ Management) — если есть асинхронные интеграции.
8. **Mermaid** или PlantUML — схемы последовательности в документации.

::: tip Попросите доступы заранее
Доступ к UI брокеров, логам, трассировке и тестовым стендам смежных систем часто оформляется неделями. Запрашивайте их на этапе выявления требований, а не накануне приёмки.
:::

## Как хранить коллекции запросов в git {#collections-in-git}

Коллекция запросов — такой же артефакт интеграции, как спецификация. Если она лежит в репозитории рядом с OpenAPI:

- изменения проходят code review вместе с изменениями контракта;
- видна история: кто, когда и зачем поменял запрос;
- новые участники получают рабочие примеры одним `git clone`;
- коллекцию можно прогонять в CI как смоук-тест.

Подходят инструменты, которые хранят запросы в **текстовых файлах**: Bruno, файлы `.http` (IntelliJ HTTP Client, VS Code REST Client), Kreya. Экспорт коллекции Postman в JSON тоже можно класть в git, но это один большой файл, диффы которого тяжело читать.

### Файлы .http {#http-files}

Формат понимают VS Code REST Client и IntelliJ HTTP Client (синтаксис совпадает в базовой части). Запросы разделяются строкой `###`, переменные подставляются через двойные фигурные скобки.

```http
@baseUrl = https://api-test.example.com/v1

### Получить токен
# @name auth
POST https://auth-test.example.com/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id={{clientId}}&client_secret={{clientSecret}}

### Получить заказ
GET {{baseUrl}}/orders/42
Authorization: Bearer {{auth.response.body.access_token}}
Accept: application/json

### Создать заказ
POST {{baseUrl}}/orders
Authorization: Bearer {{auth.response.body.access_token}}
Content-Type: application/json
Idempotency-Key: 6f1c2a4e-1b7d-4a4f-9c1e-2d3b4c5d6e7f

{
  "customerId": "c-1001",
  "items": [
    { "sku": "SKU-1", "quantity": 2 }
  ]
}
```

::: info Различия диалектов
Синтаксис ссылки на ответ другого запроса (`auth.response.body.access_token`) — это VS Code REST Client. В IntelliJ HTTP Client значение обычно сохраняют в response-скрипте через `client.global.set(...)` и используют как обычную переменную. Если команда работает в разных IDE — договоритесь о едином подмножестве синтаксиса.
:::

Окружения и секреты выносят в отдельные файлы:

```text
api/
├── openapi.yaml
└── requests/
    ├── orders.http
    ├── http-client.env.json            # окружения: test, preprod (без секретов) — в git
    └── http-client.private.env.json    # client_secret, пароли — в .gitignore
```

```json
{
  "test":    { "baseUrl": "https://api-test.example.com/v1", "clientId": "integration-test" },
  "preprod": { "baseUrl": "https://api-pre.example.com/v1",  "clientId": "integration-pre" }
}
```

### Bruno {#bruno}

Bruno хранит коллекцию как папку: один запрос — один файл (`.bru` или, в новых версиях, YAML), окружения — в подпапке `environments`. Секреты можно держать в файле `.env` (в `.gitignore`) и ссылаться на них из окружений.

```text
orders-api/
├── bruno.json
├── environments/
│   ├── test.bru
│   └── preprod.bru
├── .env                 # секреты, в .gitignore
├── Auth/
│   └── Get token.bru
└── Orders/
    ├── Get order.bru
    └── Create order.bru
```

```text
meta {
  name: Get order
  type: http
  seq: 1
}

get {
  url: {{baseUrl}}/orders/42
  body: none
  auth: bearer
}

auth:bearer {
  token: {{accessToken}}
}

tests {
  test("status is 200", function() {
    expect(res.getStatus()).to.equal(200);
  });
}
```

Прогон коллекции из командной строки или CI — через Bruno CLI (пакет `@usebruno/cli`):

```bash
cd orders-api
bru run --env test
```

::: warning Секреты не коммитим
Ни в `.http`-файлах, ни в окружениях Bruno/Postman не должно быть боевых паролей, client_secret и токенов. Добавьте файлы с секретами в `.gitignore` до первого коммита. Если секрет всё-таки попал в историю git — считайте его скомпрометированным и перевыпускайте: удаление из последнего коммита его не спасает.
:::
